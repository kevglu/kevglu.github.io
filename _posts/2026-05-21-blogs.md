I wrote the second chapter of my dissertation around 2019-2021. The Matlab code has been sitting in my Dropbox folder ever since. Let claude.ai do the hard work and translate it to a nice well-behaved python program.


## The beginning 26-05-21
I got a 20 EUR claude Pro license. Setup is easy. I run claude via VS Code, though I might switch g

## Initial codebase scanning
Initially I let claude analyse the whole codebase using `/init` but I stopped the process because the codebase contains many irrelevant files used for variants of the main models. Instead I told claude to focus on two main files and work backwards from there. The initial interpretation of my codebase was quite good. Claude understood the pipeline and even figured out how parameters are set (calibration, steady states, parameters set in SMM). The codebase description is saved in CLAUDE.md.

My pipeline looks like this:
1. Options
2. Retrieve parameters priorly identified via SMM (or current guess for best parameters)
3. In deterministic steady state solve for remaining parameters.
4. Set up grids and precompute (there is a massive computational advantage in precomputation outside the main loop)
5. Solve using value function iteration
6. Compute the full set of policy functions
7. Simulate the model

Claude has problems understanding the link between quantitative assumptions and code, e.g. a near zero standard deviation turns off a stochastic process. Claude interprets the process' contribution as as "small".

## Planning
Switch `/model` to OPUS. That's the more capable and expensive model. I use it only for planning. The plan is then executed by the cheaper SONNET (4.6) model.
The plan looks fine, it closely follows my original script.

## Execution
SONNET translates the code in about a working day.
Computation could be much quicker if I allowed it to run `python *`.

Apart from writing lots of unit tests, claude wrote a faithful translation of the original Matlab code. I urged it to improve on my code in one or two instances. Numpy was more foregiving than Matlab and allowed calude to fix an inefficiency I always disliked. 

## Output
The python translation is considerably faster than the Matlab code. Solving the RBC variant of the model takes around 7.5 minutes to run in Matlab and nearly 3 minutes in python. Solving the LRR variant of the model takes around 3.5 minutes in Matlab and 71 seconds in the python translation. A part of the improvement is due to a fixed inefficiency in the grid setup. So it is not a 1:1 comparison. 

The python translation reproduces the code up to small differences - probably due to random number generation.

## Risks
- Claude did not generate a virtual environment. It installed dependencies and the new code right into my main python application!

## Bugs/Annoyances
- So many tests. Claude treats tests like a business consultant treats power point slides: generate tons to showcase your effort. Tests need a serious weeding out
