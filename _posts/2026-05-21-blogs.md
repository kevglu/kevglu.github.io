I wrote the second chapter of my dissertation around 2019-2021. The Matlab code has been sitting in my Dropbox folder ever since. The code is a typical scientific haystack with dozens of different variants, parametrizations and occasional curses ("bullshit"). Let claude.ai do the hard work and translate it to a nice well-behaved python program.


## The beginning 26-05-21

I got a 20 EUR claude Pro license. Initially I let claude analyse the whole codebase using `/init` but I stopped the process because the codebase contains too many irrelevant files. Instead I told claude to focus on two main files and work backwards from there. The initial interpretation of my codebase was quite good. Claude understood the pipeline and even figured out how parameters are set (calibration, stochastic steady states, GMM). The codebase description is saved in CLAUDE.md.

But, claude seems to have problems understanding the link between quantitative assumptions and code, e.g. a near zero standard deviation essentially turns off a stochastic process. Claude interprets the process' contribution as as "small". 
It seems that the "quantitative gut feeling" so far remains an edge of macroeconomists over LLMs.

## Planning
Switch `/model` to OPUS. That's the more capable and expensive model. I use it only for planning. The plan is then executed by the cheaper SONNET (4.6) model.
The plan looks fine, it closely follows my original script.

## Execution
SONNET translates the code in about a day. Computation could be much quicker if I allowed it to run `python *`.
(link to switching to github).

## Risks
- Claude did not generate a virtual environment. It installed dependencies and the new code right into my main python application!

## Bugs/Annoyances
- So many tests. Claude treats tests like a business consultant treats power point slides: generate tons to showcase your effort. Tests need a serious weeding out
